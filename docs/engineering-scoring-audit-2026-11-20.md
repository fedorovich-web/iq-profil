# IQ.Профиль — аудит оценивания и банка графических заданий

Дата: 20.11.2026
Область: локальная QA-копия проекта IQ.Профиль.
Исходная база проверки: `850fab4`. Git-релиз и production-развёртывание рассматриваются отдельно от результатов QA.

## 1. Правила оценивания

- Один правильный ответ = один балл. Неверные ответы = ноль баллов. Время не влияет на баллы.
- Сервер принимает идентификатор выбранного варианта и проверяет его принадлежность конкретному вопросу.
- Результат считается внутри транзакции, после блокировки попытки и проверки сохранённых ответов.
- Оценивание привязано к `test_code`, `question_revision`, `question_count`. Контент чужого теста, другого вопроса или ревизии не засчитывается.
- `question_count` фиксируется при создании попытки. Знаменатель для завершённого отчёта не берётся из текущего каталога.
- Контрольная SHA-256 сумма банка включает вопросы, графические состояния, объяснения и ключи ответов. При её изменении активная попытка не продолжает оценивание.
- Завершённый балл не пересчитывается при последующих изменениях банка. Недостоверная детализация результатов не показывается.
- Для старых попыток, созданных до механизма контрольных сумм, отсутствие `bank_fingerprint` является допустимым признаком прежнего формата, а не подтверждением неизменности их банка.

Основные компоненты: `app/Support/AttemptScoring.php`, `QuestionBankIntegrity.php`, `OptionPresentation.php`.

## 2. Ответы и графика

- Сохранены каталоги версий 5, 6 и 7. Актуальная ревизия: **8**, 25 заданий, по шесть вариантов.
- Вопрос №18 переработан на композицию поворотов с объединением элементов.
- В вопросе №24 представлены три квадрата разного размера: правильное решение нельзя выбрать простым поиском единственного квадрата.
- Исправлен опубликованный шестипозиционный цикл правильных букв. В ревизии 8 исходный порядок вариантов определяется неизменяемой для релиза перестановкой.
- Для каждой новой попытки дополнительно создаётся собственный порядок отображения вариантов, устойчивый к обновлению страницы и возврату к предыдущему вопросу.
- Старые попытки с `option_shuffle_seed = NULL` сохраняют исторические A–F. В отчёте новой попытки буквы соответствуют увиденным пользователем.
- Векторная SVG-графика проверена на обрезания, пустые рисунки, горизонтальное переполнение и нестабильное положение блоков.
- Математически проверены все 150 альтернатив по предписанным правилам. Это **не** доказывает отсутствие всех возможных альтернативных человеческих интерпретаций.

## 3. Готовность к другим тестам и увеличению числа вопросов

В БД введено разграничение по `test_code`; система оценивания и пилотной статистики работает независимо от константы числа вопросов текущего каталога.

Проверены тестовый набор из 37 вопросов, отдельная ревизия из 300 вопросов, межтестовая изоляция и отказ при изменении числа вопросов после начала попытки.

Ограничение: пользовательский UI, маршрутизация и генератор задач для дополнительных тестов пока не реализованы. Для каждого нового теста потребуется регистрация самостоятельного опубликованного банка, определение графического формата и пользовательские экраны. Не следует считать другие тесты уже доступными.

Перед любым release: выполнить резервное копирование целевой БД, проверить совместимость миграций с целевой СУБД, развёрнуть код в staging, выполнить `php artisan migrate --force`, затем `php artisan db:seed --class=QuestionSeeder --force`. Новый банк должен содержать ровно 25 вопросов ревизии 8; ранее опубликованные версии не должны изменяться. Выполнить `php artisan test`, `npm run build`, browser E2E и ручную проверку основных сценариев на staging.

В рабочей копии QA выполнены миграции и сидирование ревизии 8. **Production не обновлялся**.

## 6. Ограничения и следующие задачи

1. Содержательная экспертиза всех 25 задач независимыми рецензентами и последующий пилот пользователей — для поиска альтернативных решений, оценки сложности и дискриминации заданий.
2. При необходимости нормативного IQ: отдельная психометрическая методология, валидизация и построение возрастных норм; не выводить числовой IQ из сырого процента.
3. Перед первым production-развёртыванием перепроверить миграции на реальной СУБД, восстановление из backup, идемпотентность сидирования и эксплуатационные метрики.
4. Подключение будущих тестов: каталог тестов, собственные версии банков, UI/маршрутизация и разграничение попыток. Оценочный модуль к этому подготовлен, но веб-функциональность пока предназначена для матриц.
